# KayGPT Database Schema

PostgreSQL 16 (14+ works). Application tables are managed by **Alembic** (`backend/alembic/`). LangGraph's checkpoint tables are created by `AsyncPostgresSaver.setup()` at startup (idempotent) and are not part of the Alembic history.

## Entity relationships

```text
users ─┬─< user_sessions          (CASCADE)
       ├── user_preferences (1:1)  (CASCADE)
       ├─< conversations ─┬─< messages   (CASCADE)
       │                  ├─< documents  (CASCADE)
       │                  └─< memories   (SET NULL: memories outlive the chat they came from)
       ├─< documents               (CASCADE; conversation_id NULL = available in all chats)
       └─< memories                (CASCADE)

conversations.id  ==  LangGraph checkpoints.thread_id (text)
```

All primary keys are UUIDs (generated by the application). All timestamps are `timestamptz` (UTC).

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |

| created_at | timestamptz | |
| expires_at | timestamptz | indexed; expired rows are purged on each login |

### `user_preferences`
| Column | Type | Notes |
|---|---|---|
| user_id | uuid PK, FK → users, CASCADE | |
| default_model | varchar(100) null | validated against the model registry |
| theme | varchar(10), default 'system' | system / light / dark |

### `conversations`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | also the LangGraph thread id |
| user_id | uuid FK → users, CASCADE | |
| title | varchar(200) | from the first message, renamable |
| model_id | varchar(100) null | last model used |
| created_at / updated_at | timestamptz | `updated_at` bumped on every turn |

Index: `(user_id, updated_at)`: sidebar listing.

### `messages`
UI transcript. The agent's own context lives in the checkpointer; this table is never fed to the LLM.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| conversation_id | uuid FK → conversations, CASCADE | |
| role | varchar(20) | CHECK `user`/`assistant` |
| content | text | Markdown |
| status | varchar(20), default 'complete' | CHECK `complete`/`stopped`/`error` |
| model_id | varchar(100) null | |
| metadata | jsonb, default '{}' | e.g. `{"tools": ["web_search"]}` |
| created_at | timestamptz, default `clock_timestamp()` | `clock_timestamp()` (not `now()`) so rows written in one transaction still order correctly |

Index: `(conversation_id, created_at)`: keyset pagination (`before` cursor).

### `memories`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | also the vector id in the `kaygpt_memories` Chroma collection |
| user_id | uuid FK → users, CASCADE | |
| conversation_id | uuid FK → conversations, SET NULL | where it was learned |
| content | text | normalized whitespace, ≤ 2000 chars |
| content_hash | varchar(64) | SHA-256 of normalized, case-folded content |
| source | varchar(20) | `agent`, `user`, `imported` |
| created_at | timestamptz | |

Constraints: UNIQUE `(user_id, content_hash)` (exact-duplicate guard, race-safe). Index `(user_id, created_at)`.

### `documents`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | vectors use ids `"{document_id}:{chunk_index}"` |
| user_id | uuid FK → users, CASCADE | |
| conversation_id | uuid FK → conversations, CASCADE, null | NULL = searchable in all the user's chats |
| filename | varchar(255) | display only, path components stripped |
| content_type / extension | varchar | from the validated type |
| size_bytes | bigint | |
| sha256 | varchar(64) | of the original file |
| storage_key | varchar(512) unique | `users/{user_id}/{document_id}{ext}` |
| status | varchar(20) | CHECK `pending`/`processing`/`ready`/`failed` |
| error_message | varchar(500) null | user-safe failure reason |
| chunk_count | int | |
| created_at / updated_at | timestamptz | |

Indexes: `(user_id, created_at)`, `(conversation_id)`, `(status)`. At startup, rows stuck in `pending`/`processing` for more than 15 minutes are marked `failed` (interrupted by a restart).

## LangGraph checkpoint tables

Created by `langgraph-checkpoint-postgres` (`checkpoints`, `checkpoint_blobs`, `checkpoint_writes`, `checkpoint_migrations`). Keyed by `thread_id = str(conversation.id)`. Deleting a conversation calls `adelete_thread`.

## Data outside PostgreSQL

| Data | Store | Rebuildable? |
|---|---|---|
| Document chunks + embeddings | Chroma `kaygpt_documents` (metadata: user_id, conversation_id or "", document_id, filename, chunk_index) | Yes, from stored files: `python -m scripts.reindex --documents` |
| Memory embeddings | Chroma `kaygpt_memories` (metadata: user_id) | Yes, from `memories`: `python -m scripts.reindex --memories` |
| Original uploads | Storage backend (local disk or S3) | No: back it up |

## Migrations

```bash
cd backend
uv run alembic upgrade head                                   # apply
uv run alembic revision --autogenerate -m "describe change"   # create (then review + ruff format)
uv run alembic downgrade -1                                   # roll back one
```
- `tests/integration/test_postgres_persistence.py::test_migrations_match_models` fails if models and migrations drift.
- Production: Render runs `alembic upgrade head` as the `preDeployCommand`; the Docker entrypoint runs it when `RUN_MIGRATIONS=true` (default).
- Revision `5f7066ac907c`: initial schema.

## Legacy SQLite data

`backend/scripts/import_legacy_sqlite.py` copies the pre-2.0 `data/chatbot_memory.db` (conversations, messages, memories) into PostgreSQL under one existing user and seeds each conversation's checkpoint from its transcript. Run `python -m scripts.reindex --memories` afterwards. The source file is opened read-only.
